## 導入手順（参考程度に）
1. ダウンロードしたZIPファイルを展開する
2. conf.phpを開いて設定する
3. FTPクライアント等でサーバーへファイルをアップロードする（他のファイルと混ざらないよう専用ディレクトリを作るのがおすすめです）
4. readme.mdに記載のパーミッションを設定する
5. ブラウザで`_setup.php`（パッケージに同梱されている独立ツール。conf.phpやinstall.phpの一部ではありません）へアクセスし、管理者パスワードを設定する。完了すると、このツールは任意の名前（推測されにくいデフォルト名が提案されます）に自動でリネームされます — 後でパスワードを変更する際に必要になるので、新しい名前・URLを控えておいてください。
6. （現在は不要 — 管理者パスワードはconf.phpではなく`_setup.php`によって専用ファイルへ直接書き込まれます）
7. ブラウザでbbs.phpにアクセスし、投稿できるか確認する
8. ログファイル（bbs.log、log/内のファイル等）が置かれているURLにブラウザでアクセスし、見えてしまわないか確認する（見えてしまう場合は.htaccess等で隠してください）

## トラブルシューティング
### 既存サイトのアップグレード（管理者パスワードの移行）
RC8以降、管理者パスワード（ADMINPOST/ADMINKEY）はconf.phpの外、このテンプレートに含まれずinstall.phpによって上書きされることもない固定名ファイル`local.php`に置かれます。install.phpは、アップグレード対象サイトの既存conf.phpに空でないADMINPOSTがあることを検出すると、**旧パスワード**（本人確認用）と**新パスワード**の入力を求める移行フォームを表示します。管理モード移行キーワード（ADMINKEY）は自動的に引き継がれ、専用の入力欄はありません。

- 旧パスワードの確認に成功すると、新パスワードで`local.php`が書き込まれ、通常どおりインストールが進みます。
- 確認に失敗すると、**インストール全体が中止されます**（ファイルは一切インストールされず、バックアップや上書きも行われません）。自分が管理していないサイトの管理者アカウントを他人に乗っ取られるのを防ぐためです。
- 本当に旧パスワードを忘れてしまった場合は、サーバー上の既存conf.phpを開き、`ADMINPOST`の値を手動で空文字列にしてください。これによりinstall.phpは新規インストールとして扱うようになり、新規インストールと同様に、その後`_setup.php`経由でまったく新しいパスワードを設定できます。

## 推奨パーミッション設定
パーミッションの設定を誤ると、不具合やデータ漏洩（投稿者のIPアドレスやリモートホストなど）の原因になりますので、正しく設定されているか必ず確認してください。

```
[ファイル構成]
|-- bbs.cnt   600（書き込み可）    参加者リスト記録ファイル（空のテキストファイル）
|-- bbs.log   600（書き込み可）    ログファイル（空のテキストファイル）
|-- conf.php  644（読み取り専用）  設定用
|-- bbs.php 644（読み取り専用）    掲示板本体スクリプト
|-- readme.md                       説明書（このファイル）
|
|-- vanish.js                       ワードフィルタリング用スクリプト
|
|
+-- archive/  700（書き込み可）    ZIPアーカイブ保存ディレクトリ
+-- count/    700（書き込み可）    カウンター出力ディレクトリ
+-- log/      700（書き込み可）    メッセージログ（生ログ）保存ディレクトリ
+-- sub/      755（読み取り専用）  サブモジュール保存ディレクトリ
    |
    |-- bbsadmin.php    644（読み取り専用）    管理モジュール
    |-- bbslog.php      644（読み取り専用）    ログビューアモジュール
    |-- bbstree.php     644（読み取り専用）    ツリー表示モジュール
    |-- phpzip.inc.php  644（読み取り専用）    ZIPファイル作成ライブラリ
```

PHPがApacheモジュールとして動作している場合、bbs.phpは読み取り専用のままで構いませんが、
CGIとして動作している場合は、bbs.phpを755（実行可能）に設定する必要があります。

## 既知の不具合：
* （移行に関する注意、RC13以降）RC10〜RC12で追加された3つのブラウザ単位JS機能（treehide・longpostfilter・latexrender）は、当初ON/OFF状態をlocalStorageに保存していた。RC13ではこれらの設定をサーバークッキー（`ksphp_js`）へ移行したが、移行措置として各スクリプトは既存のlocalStorage値がある場合、それを引き続き優先する。そのため、RC10〜RC12時点であるブラウザで機能を明示的にOFFにしていた場合、新しいJS設定パネルでONに切り替えても効果がないように見える — 古いlocalStorageの`0`が勝ってしまうため。修正はブラウザごとに1回限りの操作で済む：パネルで機能をOFF→ONと切り替え直すか、古いキー（`ksphp_treehide_enabled`・`ksphp_longpost_enabled`・`ksphp_latex_enabled`）を削除する。新規インストールや、RC10〜RC12を経験していないブラウザには影響しない。
* （2026-08-01発見・修正、RC13）longpostfilter.jsの投稿ごとの「折りたたむ」リンクが、実際に行数閾値を超えているかどうかに関わらず、すべての投稿に表示されてしまっていた — 折りたたまれていない表示経路が、リンクを表示したまま無条件にexpand()を呼んでいたため。実際に折りたたまれていた（＝閾値を超えていた）投稿が手動で再展開された後にのみ折りたたむリンクが表示されるよう修正。
