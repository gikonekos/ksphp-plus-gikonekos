## 설치 절차 (참고용)
1. 다운로드한 ZIP 파일의 압축을 해제한다
2. conf.php를 열어 설정한다
3. FTP 클라이언트 등을 사용해 파일을 서버에 업로드한다(다른 파일과 섞이지 않도록 전용 디렉터리를 만드는 것을 권장합니다)
4. readme.md에 기재된 권한을 설정한다
5. 웹 브라우저로 `_setup.php`(패키지에 동봉된 독립 도구. conf.php나 install.php의 일부가 아닙니다)에 접속하여 관리자 비밀번호를 설정한다. 완료되면 이 도구는 임의의 이름(추측하기 어려운 기본값이 제안됩니다)으로 자동으로 이름이 변경됩니다 — 이후 비밀번호를 변경할 때 필요하므로 새 이름/URL을 반드시 기록해 두세요.
6. (더 이상 필요 없음 — 관리자 비밀번호는 conf.php가 아니라 `_setup.php`에 의해 전용 파일에 직접 기록됩니다.)
7. 웹 브라우저로 bbs.php에 접속하여 게시할 수 있는지 확인한다
8. 로그 파일(bbs.log, log/ 내 파일 등)이 있는 URL에 브라우저로 접속하여 보이는지 확인한다(보인다면 .htaccess 등으로 숨겨주세요)

## 문제 해결
### 기존 사이트 업그레이드(관리자 비밀번호 이전)
RC8부터 관리자 비밀번호(ADMINPOST/ADMINKEY)는 conf.php 밖, 이 템플릿에 포함되지 않고 install.php에 의해 덮어써지지도 않는 고정 이름 파일 `local.php`에 저장됩니다. install.php는 업그레이드 대상 사이트의 기존 conf.php에 비어 있지 않은 ADMINPOST가 있음을 감지하면, **기존 비밀번호**(본인 확인용)와 새로 설정할 **새 비밀번호** 입력을 요구하는 이전 폼을 표시합니다. 관리 모드 키워드(ADMINKEY)는 자동으로 이어지며, 별도의 입력란은 없습니다.

- 기존 비밀번호 확인에 성공하면, 새 비밀번호로 `local.php`가 기록되고 설치가 정상적으로 진행됩니다.
- 확인에 실패하면 **설치 전체가 중단됩니다**(파일이 전혀 설치되지 않고, 백업이나 덮어쓰기도 이루어지지 않습니다) — 자신이 관리하지 않는 사이트의 관리자 계정을 타인이 탈취하는 것을 방지하기 위함입니다.
- 정말로 기존 비밀번호를 잊어버린 경우, 서버의 기존 conf.php를 열어 `ADMINPOST` 값을 수동으로 빈 문자열로 만드세요. 그러면 install.php가 신규 설치로 취급하게 되어, 신규 설치와 마찬가지로 이후 `_setup.php`를 통해 완전히 새로운 비밀번호를 설정할 수 있습니다.

## 권장 권한 설정
권한 설정을 잘못하면 문제나 데이터 유출(게시자의 IP 주소나 원격 호스트 등)의 원인이 되므로, 반드시 올바르게 설정되어 있는지 확인하세요.

```
[파일 구조]
|-- bbs.cnt   600 (쓰기 가능)      참여자 목록 기록 파일 (빈 텍스트 파일)
|-- bbs.log   600 (쓰기 가능)      로그 파일 (빈 텍스트 파일)
|-- conf.php  644 (읽기 전용)      설정용
|-- bbs.php 644 (읽기 전용)        게시판 본체 스크립트
|-- readme.md                       설명서 (이 파일)
|
|-- vanish.js                       단어 필터링용 스크립트
|
|
+-- archive/  700 (쓰기 가능)      ZIP 아카이브 저장 디렉터리
+-- count/    700 (쓰기 가능)      카운터 출력 디렉터리
+-- log/      700 (쓰기 가능)      메시지 로그(원본 로그) 저장 디렉터리
+-- sub/      755 (읽기 전용)      서브모듈 저장 디렉터리
    |
    |-- bbsadmin.php    644 (읽기 전용)    관리 모듈
    |-- bbslog.php      644 (읽기 전용)    로그 뷰어 모듈
    |-- bbstree.php     644 (읽기 전용)    트리 보기 모듈
    |-- phpzip.inc.php  644 (읽기 전용)    ZIP 파일 생성 라이브러리
```

PHP가 Apache 모듈로 동작하는 경우 bbs.php는 읽기 전용으로 두어도 되지만,
CGI로 동작하는 경우에는 bbs.php를 755(실행 가능)로 설정해야 합니다.

RC13에서 이 설정을 서버 쿠키(`ksphp_js`)로 옮겼으며, 마이그레이션을 위해 각 스크립트는 기존 localStorage 값이 있으면 이를 계속 우선함. 그 결과, RC10~RC12 시점에 어떤 브라우저에서 해당 기능을 명시적으로 OFF로 해두었던 경우, 새 JS 설정 패널에서 ON으로 전환해도 효과가 없는 것처럼 보임 -- 오래된 localStorage의 `0`이 우선되기 때문. 수정은 브라우저별로 한 번만 하면 됨: 패널에서 기능을 껐다 켰다 다시 전환하거나, 오래된 키(`ksphp_treehide_enabled`, `ksphp_longpost_enabled`, `ksphp_latex_enabled`)를 삭제하면 됨. 신규 설치 및 RC10~RC12를 거치지 않은 브라우저는 영향 없음.
* (2026-08-01 발견 및 수정, RC13) longpostfilter.js의 게시물별 "折りたたむ"(접기) 링크가, 실제로 줄 수 임계값을 초과했는지 여부와 관계없이 모든 게시물에 표시되고 있었음 -- 접히지 않은 렌더링 경로가 링크가 표시된 상태로 무조건 expand()를 호출했기 때문. 실제로 접혀 있던(즉 임계값을 초과했던) 게시물이 수동으로 다시 펼쳐진 후에만 접기 링크가 나타나도록 수정.
* (2026-08-01 발견 및 수정, RC12-02) RC11 인계 노트에서는 수식 형태의 설정 값(예: `MAXOLDLOGSIZE`의 `4 * 1024 * 1024`)을 저장 시 따옴표 없이 유지하기 위한 `$was_numeric_expr` 확인이 `ksphp_conf_apply_review()`에 추가되었다고 되어 있었으나, 실제로는 출시된 코드(RC11, RC12 모두)에 존재하지 않았음 -- 기존의 단순 숫자 확인만 남아 있었음. 실제 사이트의 `MAXMSGSIZE` 값(`'250*120*128*256*128'`, 이전 설치 실행 시 따옴표 붙은 문자열로 저장됨)이 `procForm()`의 콘텐츠 길이 비교에서 PHP의 비숫자 값 경고를 일으켰고, 이로 인해 HTTP 응답이 손상되어 브라우저에서 `ERR_CONTENT_DECODING_FAILED`로 나타난 것을 통해 발견됨. 해당 확인은 이제 실제로 구현되었음. 중요한 제한 사항: 이는 앞으로의 설치/마이그레이션에서만 버그를 방지하며, 이미 따옴표 붙은 문자열로 저장된 conf.php 값을 자동으로 복구하지는 않음(확인 폼은 기존의 따옴표 붙은 값을 그대로 다시 제출할 뿐임). 이미 손상된 수식 형태의 키는 conf.php를 수동으로 수정하거나, 확인 폼에서 값을 다시 입력하여 제출해야 함.
* 로그 검색 시 \&nbsp;가 대량으로 나타남
* (2026-08-01, install.php의 conf-review 테스트 중 발견. 같은 날 수정 -- 근본 원인은 위 할 일 목록 참고) `ksphp_conf_parse_entries()`의 항목 경계 스캐너가, 따옴표가 붙은 'KEY' =>와 같은 문자열을 포함하는 주석 처리된 예시가 바로 앞에 있는 경우 키를 잘못 인식하고 있었음(예: 주석 처리된 TMPL_MSG/TMPL_ENVLIST 뒤의 HOSTNAME_POSTDENIED, 각자의 주석 처리된 예시 뒤의 CHECKCOUNT/MINPOSTSEC/MAXPOSTSEC). 4곳의 호출부(`ksphp_conf_merge()`, `ksphp_conf_build_review()`, `ksphp_conf_apply_review()`, `ksphp_parse_module_array()`) 모두에서, 키 이름 매칭 전에 앞쪽 주석 줄을 제거하도록 수정. install.php 측의 방어적 "raw" 폴백은 안전장치로 남겨두었으나, 실제 운영에서는 더 이상 발동하지 않을 것으로 예상됨.
* (2026-08-01, qptns.com에서 실기기 확인. 같은 날 수정 -- 자세한 내용은 할 일 목록 참고) install.php의 conf-review 화면이 ZIPDIR을 잘못 필수 항목으로 표시하고 있었음. 실제로는 빈 ZIPDIR도 "ZIP 로그를 생성하지 않음"이라는 유효한 설정임. OLDLOGFILEDIR 및 CNTFILENAME에 대해서도 동일한 문제(각자의 conf.php 주석에서 확인된 "공란=기능 비활성화" 패턴)를 수정.
* (2026-08-01 구현 완료) 일별/월별 과거 로그 순환용 파일에 대한 "파일이 존재하지 않아 새로 생성했습니다"라는 자동 생성 알림이, 진정한 최초 설정 시(OLDLOGFILEDIR 내에 같은 확장자의 다른 과거 로그 파일이 존재하지 않는 경우)에만 표시되도록 함. 일/월 경계마다 날짜가 붙은 새 파일이 생성되는 일반적인 순환(기존 과거 파일이 이미 존재하는 상태)에서는 이 알림이 더 이상 표시되지 않음. 의도적으로 가벼운 범위로 구현: "해당 기간의 첫 게시물인지"를 달력 계산으로 판단하는 대신, OLDLOGFILEDIR 내에 다른 과거 로그 파일이 이미 존재하는지에 대한 디렉터리 목록 확인만 수행.
* (2026-08-01 발견 및 수정, RC14-02, qptns.com/test/에서의 실기기 테스트를 통해) ayashiibreaker.js의 줄바꿈 목표값이 RC14의 초기 수정(일본어 줄은 configuredLen-2) 이후에도 여전히 너무 빡빡했음: 특정 긴 테스트 문장에 대한 실기기 검증을 거쳐, 일본어와 ASCII 모두 configuredLen-12로 올림. 별도로, ASCII(영어) 단어 경계 줄바꿈에도 자체적인 버그가 있었음: 단어를 추가하기로 확정한 "이후"에만 임계값 초과 여부를 확인했으며, 목표 길이보다 긴 단어(예: "ayashiibreaker.js", "word-boundary")는 전혀 분할하지 않았기 때문에, 여백 설정과 관계없이 한 줄이 잘리지 않은 채로 남을 수 있었음. 줄을 배열에 누적하고, 지나치게 긴 단어는 강제로 문자 단위로 분할하며, 추가 전에 후보의 길이를 확인하는 방식으로 재작성하여, ASCII 쪽 줄은 이제 설정된 상한을 반드시 지키도록 보장됨.
